# Лабораторная работа № 2. Технологии программирования

## Вариант 4. Магазин товаров для быта

Магазин «Дом и быт» ведёт учёт покупателей и рассчитывает накопительную скидку по числу оформленных покупок. Покупатель может зарегистрироваться, выбрать товар из каталога, оформить покупку, открыть квитанцию и посмотреть свою историю в личном кабинете. В панели Django по адресу `/admin/` администратор может редактировать каталог и просматривать покупателей и оформленные покупки.

### Правила скидки

За одну покупку считается одно подтверждённое оформление товара. Счётчик ведётся по аккаунту и учитывает все товары. Скидка на текущую покупку определяется по числу ранее оформленных покупок.

| Покупок до оформления | Скидка |
| --- | ---: |
| 0–2 | 0% |
| 3–4 | 5% |
| 5–9 | 10% |
| 10 и больше | 15% |

Например, после трёх покупок контейнер за 349 ₽ обойдётся в 331,55 ₽. Сервер сохраняет цену, скидку и итоговую сумму каждой покупки в базе. Повторная отправка той же формы возвращает квитанцию существующей покупки.

## Запуск

Нужен Python 3.12. Команды ниже выполняются в PowerShell из корневой папки проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py loaddata products.yaml
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте [магазин](http://127.0.0.1:8000/) и создайте аккаунт. Для доступа к панели администратора создайте отдельную учётную запись командой `.\.venv\Scripts\python.exe manage.py createsuperuser`.

### PostgreSQL

Для быстрого запуска Django использует SQLite. Для работы с PostgreSQL создайте базу `django_db` и назначьте владельцем пользователя, под которым Django будет подключаться к базе. Задайте параметры подключения перед выполнением миграций и запуском сервера.

```powershell
$env:DATABASE_NAME = 'django_db'
$env:DATABASE_USER = 'postgres'
$env:DATABASE_HOST = '127.0.0.1'
$env:DATABASE_PORT = '5432'
$password = Read-Host 'Пароль PostgreSQL' -AsSecureString
$env:DATABASE_PASSWORD = [System.Net.NetworkCredential]::new('', $password).Password
```

После настройки выполните `migrate` и `loaddata` из раздела выше. Для запуска тестов роль PostgreSQL должна иметь право создавать тестовую базу. Миграция сохраняет покупки из исходной схемы. Для старых записей сумма восстанавливается по цене из каталога, а связь с аккаунтом остаётся пустой.

## Архитектура и инструменты

Проект использует Django 5.2, Python, PostgreSQL или SQLite, HTML и CSS. Psycopg подключает PostgreSQL. PyYAML используется для загрузки фикстуры с девятью товарами.

В терминах MVC модели `Product`, `Purchase` и пользователь Django хранят каталог, покупки и данные покупателей. Обработчики в `shop/views.py` принимают запросы из `shop/urls.py`, проверяют формы и вызывают расчёт из `shop/services.py`. HTML-шаблоны отображают каталог, оформление покупки, квитанцию и личный кабинет.

Индивидуальное задание выполнено в ветке `household-loyalty` и объединено с `main`. Проверки выполняются локально.

## Проверки и выводы

```powershell
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

На PostgreSQL прошли все 18 тестов. Они проверяют пороги скидок, сохранение цены в квитанции, повторную отправку формы, изоляцию истории, миграцию старых покупок и два одновременных заказа на границе порога. На SQLite проходят 17 тестов, проверка блокировки строк выполняется на PostgreSQL. В браузере проверены регистрация, оформление четырёх покупок разных товаров и отображение скидки 5% в квитанции и личном кабинете.

Отдельный модуль расчёта позволяет менять шкалу скидок и проверять её независимо от веб-страниц. Транзакция сохраняет покупку вместе с рассчитанной суммой, поэтому история позволяет восстановить условия каждого заказа.
